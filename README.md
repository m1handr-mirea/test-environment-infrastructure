# Стенд автоматического развертывания тестовых сред

Для запуска нужны Python 3.11+, включённый Docker Engine с Compose v2
и терминал macOS или Linux. В Docker Desktop используется локальный контекст.
Команды выполняются из папки стенда. Для первой сборки нужен доступ
к Docker Hub и PyPI.

```bash
python3 envctl.py up feature-a
python3 envctl.py up feature-b
python3 envctl.py status feature-a
python3 envctl.py logs feature-a
python3 envctl.py check feature-a
```

Команда `up` выводит адрес после прохождения проверок. Откройте оба адреса
в браузере и сохраните метку в одной среде. Во второй среде поле останется
пустым. Порт назначает Docker. Для повторного открытия адрес можно получить
командой `check`. Имя среды должно быть уникальным среди пользователей
одного Docker Engine и содержать от 1 до 30 строчных латинских букв,
цифр и дефисов. Первый символ — буква или цифра.

```bash
python3 -u verify.py
python3 envctl.py down feature-a
python3 envctl.py down feature-b
```

`verify.py` создаёт две временные среды с уникальными именами, проверяет
их и удаляет созданные ресурсы. `down` удаляет том с данными выбранной среды.
Адреса доступны на машине с Docker. Среды используют тестовые данные.
Для запуска CI поместите содержимое этой папки в корень GitHub-репозитория.
Задание использует временную машину GitHub Actions и выполняет тот же тест.

## Двухузловой стенд Docker Swarm

Учебный кластер состоит из двух Docker Engine в контейнерах Docker-in-Docker.
На обоих узлах запускаются реплики Flask API. В каждом стеке создаются
собственная overlay-сеть, локальный том Redis и секрет подключения.
Образы шлюза и API собираются из конкретного коммита и помещаются
во внутренний реестр. Redis закреплён за управляющим узлом. Стенд показывает
размещение задач на двух узлах и независимость сред.

Запускайте команды из корня Git-репозитория на доверенной учебной машине.
Нужны локальный Docker, Python 3.11+ и Git. Для режима PR также нужны GitHub CLI
и доступ к GitHub. Вложенные Docker Engine запускаются в привилегированных
контейнерах, их сокеты и внутренний реестр не публикуются на хосте.
Шлюзы тестовых сред доступны на loopback-интерфейсе. Для каждого стека
выделяется один из восьми портов. Адрес выводится после проверки готовности.

```bash
python3 swarmctl.py bootstrap
python3 swarmctl.py up control --revision HEAD
python3 swarmctl.py status
python3 swarmctl.py down control
```

У активной среды `/api/version` показывает идентификатор стека и SHA.
Метка сохраняется при обновлении того же стека. Удаление среды удаляет и её
тестовые данные. Команда состояния показывает узлы и число реплик сервисов.

### Развёртывание по pull request

```bash
python3 -u swarmctl.py watch m1handr-mirea/test-environment-infrastructure
```

Пока процесс запущен, он сверяет открытые PR в `main` каждые 10 секунд.
Он принимает PR, открытые владельцем из ветки того же репозитория.
На создание PR выделяется стек `course-pr-НОМЕР`. Новый SHA обновляет образы
с сохранением адреса и тома. Закрытый или слитый PR приводит к удалению стека,
тома и секрета. Для одной сверки запустите ту же команду с `--once`.
Журнал содержит номер PR, проверенный SHA и локальный адрес после готовности.

GitHub Actions по-прежнему прогоняет приёмочный тест двух сред Compose
на временном исполнителе. Синхронизация PR для Swarm выполняется на узле,
где запущен кластер. На время защиты оставьте процесс в терминале.

### Диагностика

```bash
docker compose -f swarm/lab.yaml exec -T manager docker stack ps course-pr-1
docker compose -f swarm/lab.yaml exec -T manager docker service logs course-pr-1_api
docker compose -f swarm/lab.yaml stop
```

Для диагностики подставьте номер своего PR. Команда `stop` приостанавливает
учебные узлы и локальный реестр, сохраняя их тома.
